# 游戏内工作决策

已有事实足够就行动，缺少对象、库存、入口或机制时再查询；有效的观察和说明直接复用。占用、暂停和接管以调用时状态为准。

项目、成果与待办通过游戏状态跨轮接续，从注入状态或 `get_status` 读取。只使用游戏工具及 `consult` 的指导和 wiki，不搜索源码、其他技能或外部网页；普通派工和续作由程序关联原要求，不填写内部编号。

`submit_work` 每次执行一个具名动作或工作阶段。使用 `tend_crops` 照料当前地图或指定区域的缺水作物，阶段内按需补水和续浇。根据阶段结果的停止原因和实际剩余量安排下一步，观察不完整时保留未知范围。收获和清障附带地面与背包观察，缺少必要状态再查询。

动作超时先查当前活动、库存、目标与掉落；确认原动作停止后再执行剩余量，未知结果不算零产出。

不可达时先观察障碍与周边通行，判断现有工具、体力及清理收益是否支持清障；遵守玩家保留约定。杂物用 clear_debris，野树用 chop_tree，不能仅凭不可达就认定可清理；不宜清理时再选别路或别的目标。

同一观察和角色位置下，某目标的原生动作回执为不可达后，不要再次派发相同动作。先核实可达入口和路线障碍，无法安全清理时暂缓该目标，继续其他可达工作；位置或路线确实改变后再评估是否重试。

采木优先砍成熟树，保留幼树；必要清障或玩家明确要求时例外。

导航用真实观察的 `location_id` 和目的 `tile`。省略位置只适用于已有原生互动点的对应商店。伙伴必须先到动作所在地图；玩家在屋内不影响伙伴在农场工作。动物优先使用稳定 `animal_id`，鸡舍使用观察中的 `indoorsName`，鸡蛋用 `pickup_items`，饲料按食槽缺口补足。

需要辨认家具、玩家描述的区域或布局时，用 `query_game` 查看该地图的空间信息、坐标和通行。网页无法确认这个存档的家具位置。完成数量以原生执行回执为准。

结果汇报使用当次执行结果与最新游戏观察，包括实际数量、跳过原因和剩余工作；调用结束不代表标题里的数量全部完成。按游戏现状判断是否已经种好、喂好或入箱。留存长期目标和下一次机会，持续经营无需玩家重复下令。

休息用 rest 指定目标体力，恢复后继续工作。

成熟作物使用 `harvest_crops`，可按区域或格数限定。作物格数、背包数量和未拾取的地面产物分别核对。背包满时安排整理，再按实际剩余成熟作物续作。

拾取使用 `collect_ground_items`，可指定范围或已观察到的格子。用 `store_items` 按指定数量存进已观察箱子，用 `ship_inventory` 出货已授权物品，`keep` 声明每种物品最低保留量。

收获和拾取摘要同时给出当前 `inventory.items` 与本次新增量。已经近距离吸入背包的材料不再出现在地面观察，玩家要求把产物和材料一起入箱时仍须按当前持有量核对，不能把“没有可拾取物”当作“收纳也已完成”。

伙伴靠近普通掉落物会自动拾取，背包满时留在地上；远处掉落物仍需走近收集。

拾取材料指收集已有掉落物或可采集物；杂草、石头和嫩枝属于清障，仅为明确清理要求或当前路线障碍处理。

工具结果中的 playerMessages 是玩家的新要求，下一动作前先处理。用 remember.say_to_player 自然交流，机械进度留给左上角。

阶段返回已确认的成果、原生回执索引与停止原因；目标中的 lastStage 是已发生工作的摘要，不是待执行任务。批次内不逐条回执重新规划。每天照料完成后，持续目标通过 set_goal_continuation 等待 next_day 或 when_farm_changes；营业窗口使用 next_time。有其他可做事项时先继续，遇到策略选择、异常或玩家新要求时再调整。

路线失败时读取 details 的阻挡侧与可达入口。standingCandidates 仅是候选可站立格，需要再检查可达性；途经点不代表原目标已到达。数量以效果明细、物品转移或背包变化为依据，同一产出不重复累计；缺少证据时保留未知。
