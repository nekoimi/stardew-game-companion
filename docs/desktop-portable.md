# 星露谷游戏伴侣使用指南

## 启动

从本项目的 Releases 下载 `StardewGameCompanion-版本号-windows-x64.zip`，解压到可写目录，双击根目录的 **星露谷游戏伴侣.exe**。在「设置」选择含 `StardewModdingAPI.exe` 的游戏目录和伙伴来源，再点击「启动游戏」。[下载页面](https://github.com/nekoimi/star/releases)

桌面程序启动随包提供的伙伴运行时和本机 SMAPI。此时使用绿色包内的独立 `Mods` 目录，游戏原目录的其他 Mod 不会随这次启动加载。修改游玩方式、伙伴来源或客户端配置后，保存设置并重启游戏。

## 接入模型

- **启动本机模型客户端**：将 Pi、DeepSeek（dsh）、Codex 或 MiniMax Code 安装在本机并完成登录。在桌面选择客户端、模型和推理档位，客户端路径留空时自动查找。DeepSeek 模型留空时使用 `deepseek-flash`，可沿用 dsh 保存的凭据或 `DEEPSEEK_API_KEY`。
- **接续原 MiniMax Code 会话**：启动游戏后，在桌面「设置」选择原工作目录，列出并接续指定会话。连接期间让原聊天窗口闲置。身份核验针对 MiniMax Code 0.6.2，失败时保留所选绑定。需要换会话时先保存并回到游戏标题。断开桌面连接后，仍可在原客户端继续使用原会话。

## 和伙伴一起玩

进入单人存档后用桌面「指令」发送目标。伙伴模式由 AI 操作独立伙伴。自玩模式先点击「交给 AI」，在游戏窗口按 F9 可立即接管。原生游戏菜单由玩家照常操作，AI 对话、回执和待确认选择出现在桌面。

| 桌面位置 | 可以做什么 |
| --- | --- |
| 指令 → 对话 | 交代目标、补充要求、回复或关闭待确认事项。「打断并执行」会等待旧动作停止，保留已完成成果，再交给同一 Agent 处理新要求。 |
| 指令 → 工作 | 查看目标、当前动作、等待原因和最近八条执行记录，也可暂停、继续、取消当前工作或撤回所选目标。 |
| 指令 → 历史 | 按存档回看对话，每页最多 30 条。 |
| 指令 → 计划 | 查看目标日期、准备缺口、玩家需亲自完成的步骤及已核实结果。采纳会保存准备安排，实际推进仍受暂停和控制权状态约束。 |
| 伙伴消息 | 按存档查看和标记提醒，或恢复已关闭事项。过了游戏日期的提醒仍可回看。 |
| 设置 → 当前存档的伙伴设置 | 调整名字、相处方向、性格、交流频率、就寝时间和主动帮忙偏好。原会话的人格由原客户端管理。 |
| 记忆与约定 | 查看、新增、更正或删除记录。共同经历来自游戏回执。如记录已有更新，先点「读取记忆」再编辑。 |
| 用量 | 查看本包今日总量、当前存档的今日及累计用量。今日按电脑日期统计。 |

暂停、取消和改派会保留已经完成的游戏成果。空闲主动帮忙可在「设置」关闭，伙伴仍会执行已明确交代的工作。伙伴模式下，伙伴先上床不会推进玩家的游戏日期。

## 进阶设置与用量

更改接管键、思考时钟暂停开关或单次暂停上限时，先退出游戏，再编辑绿色包内 `Mods/StardewAI.Companion.Mod/config.json` 的 `TakeoverKey`、`PauseClockWhileThinking` 和 `ThinkingPauseMaxSeconds`。三项默认值分别是 `"F9"`、`true` 和 `120` 秒，下次启动生效。

模型输入包含缓存，输出包含已记录的思考用量。缺失项显示「未记录」。如需配置 API 等价估算，可把包内 Mod 的 `docs/usage-prices.example.json` 复制到同一 Mod 的 `config/usage-prices.json`，填写每百万 token 的美元单价。

## 更新与迁移

1. 在游戏中保存并退出，关闭使用旧包的桌面程序。
2. 从本项目 Releases 获取新版 ZIP，核对随附的 SHA256，将完整包解压到新目录。
3. 双击新包的 EXE，在「设置 → 从原安装导入」选择旧绿色包、旧 Mod 或原游戏目录，再检查启动设置。

导入支持工作、对话、伙伴设置、记忆与绑定的 Pi 会话。原模型或会话不可用时，可修复来源，或勾选「仅导入数据」并使用新包所选来源。保留旧目录可在需要时重新启动旧版。游戏存档继续由《星露谷物语》保存。

## 排查

- **伙伴服务断开**：在桌面点击「重连伙伴服务」和「核对旧动作」。核对后工作仍暂停，由玩家决定继续或交还控制权。原 MiniMax Code 适配器退出时，在设置中接续原会话。若缺少旧动作回执，先核对游戏结果，保存后重新进入存档。
- **模型无法启动**：确认该客户端能独立登录和对话，再核对桌面的客户端路径、模型与推理档位。错误详情见「诊断」。
- **画面或游戏时钟停顿**：桌面会标明 AI 思考或保护机制是否暂停了游戏时钟。画面与输入同时停顿时，在「诊断」检查对应时段的 `[游戏帧耗时]` 和最慢处理阶段。
