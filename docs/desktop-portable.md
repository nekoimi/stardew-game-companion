# 星露谷游戏伴侣

解压 Windows x64 绿色包到可写目录，双击 **星露谷游戏伴侣.exe**。在「设置」选择已安装的星露谷与 SMAPI，以及伙伴来源。桌面 .NET 与 Python 随包提供，模型客户端需在本机安装并登录。

选择「启动本机模型客户端」时，可用 Pi、DeepSeek（dsh）、Codex 或 MiniMax Code，各自保存模型、路径和推理档位。客户端路径留空会自动查找，DeepSeek 模型留空使用 `deepseek-flash`，可沿用本机已保存的凭据或 `DEEPSEEK_API_KEY`。旧版 Kimi、Antigravity 仍通过原 Mod 启动。

选择「接续原 MiniMax Code 会话」后启动游戏，在设置中选择原工作目录并列出会话，确认原聊天窗口保持闲置，再接续所选会话。身份校验支持 MiniMax Code 0.6.2，连接失败时保留绑定，仍可接管游戏和查看存档；更换为另一会话前先保存并回到游戏标题。退出桌面或点击「断开桌面连接」会停止桌面创建的适配器，原客户端可继续打开原会话。

点「启动游戏」，在原生游戏窗口进入单人存档，再回桌面下令。自玩模式先在桌面点「交给 AI」，游戏窗口按 F9 可立即接管；「打断并执行」等待旧动作的终态并保留已完成成果，再交给同一 Agent 处理新要求。原生游戏菜单照常出现，AI 对话、回执和待确认选择由桌面显示。

同一轮已公开发言的内容只显示一次，后续不同的回复和游戏回执仍会显示。伙伴在农场收获时，玩家可以留在农舍，随后进入农场查看。

伙伴服务退出后，点「重连伙伴服务」保留当前游戏和所选模型接入，再点「核对旧动作」。核对后工作保持暂停，点「继续」恢复工作，自玩模式还需点「交给 AI」；原 MiniMax Code 适配器退出后，在设置接续原会话。如果游戏无法提供旧动作回执，请先在游戏中核对实际结果，再保存并重新进入存档。

进入存档后，在「指令 → 工作」查看当前目标、待办、下一步、等待原因和最近八条执行记录，可暂停、继续、取消当前工作或撤回所选目标。在「指令 → 历史」回看当前存档的聊天，每页最多 30 条，可读取最新记录或查看更早的记录；多条待确认事项可在对话页选中后分别回复。

在「指令 → 计划」查看目标日期、准备缺口、需要玩家亲自完成的步骤及已有核实记录，可采纳或暂缓所选计划。采纳会保留准备安排，具体执行继续遵守暂停、自玩控制权和游戏中的时间条件。

「伙伴消息」按存档保存提醒并支持分页，可逐条标为已读；过了游戏日期的提醒仍可回看。在「指令 → 对话」可关闭所选待确认事项，需要时在「伙伴消息 → 已关闭事项」恢复。

「设置」中可保存当前存档的伙伴名字、方向、性格、交流频率、就寝时间和主动帮忙偏好。关闭主动帮忙后，伙伴仍处理已明确交代的工作。

进入存档后，在「记忆与约定」查看、新增和更正偏好、约定，或删除所选记录。共同经历的原文由游戏结果产生。若记忆同时被修改，先点「读取记忆」再编辑。

启动游戏后打开「用量」可看本绿色包按电脑日期统计的今日总用量，进入存档后可看该存档的今日与累计用量。输入已含缓存，输出已含记录中的思考用量，缺失部分显示「未记录」。费用沿用后端提供的金额或 API 等价估算，可将包内 `Mods/StardewAI.Companion.Mod/docs/usage-prices.example.json` 复制到同一 Mod 的 `config/usage-prices.json` 并填写每百万 token 的美元单价。

迁移旧安装时，先保存并退出游戏，在新解压包的「设置」里选择「从原安装导入」，可选原伙伴 Mod、游戏或旧绿色包目录。导入涵盖工作、完整聊天历史、伙伴设置、记忆和已绑定的 Pi 会话，遇到同名文件内容不同，请使用新解压的包重新导入。其他后端或会话文件缺失时，可修复来源，也可明确勾选「仅导入数据」并沿用该绿色包选择的伙伴来源。

本次启动使用包内独立 `Mods` 目录，原游戏的其他 Mod 不随这次启动加载。GUI 设置和游戏伴侣数据保存在解压目录，游戏存档由星露谷保存。更改游玩方式、伙伴来源或本机客户端配置后需重启游戏。

单人游戏连接桌面后，伙伴模式或已托管的自玩模式可在游戏窗口失焦时继续推进。这个处理只用于本次运行，暂停工作可用桌面按钮，玩家也可用游戏原生暂停。

自玩模式中，桌面会显示 AI 思考或保护机制是否暂停了游戏时钟。地点和菜单变化会及时刷新完整观察，平时约每两秒更新一次。若画面和输入一起停顿，可在「诊断」查看停顿时刻附近的 `[游戏帧耗时]`，其中包含更新间隔和伙伴处理的最慢阶段。

隔离存档同样的 720 个游戏更新内，完整观察从 26 次降到 8 次。模拟 Pi 验证了思考暂停提示、原生导航和时钟恢复。线上长回合的间歇停顿仍待复测。

## 构建与测试

构建需要 .NET 10 SDK、能编译现有 Mod 的本机游戏/SMAPI 引用和 uv。先用 `dotnet publish src/StardewAI.Companion.Desktop -c Release -o artifacts/desktop/win-x64` 生成桌面，再用 `tools/build-release.py` 的 `--desktop-source` 和 `--mod-source` 指向桌面发布目录与配套 Mod 输出。

原生扩展编译使用本地 .NET 6 SDK，子进程独立解析编译工具链。复测时把 `STAR_DOTNET_PATH` 指向该 SDK 的 `dotnet.exe`，把 `STARDEW_GAME_PATH` 指向游戏目录，再用常用 SDK 执行 `dotnet test src/StardewAI.Companion.Mod.Tests`。已验证外层 .NET 8 测试能通过独立 .NET 6 生成扩展 DLL。

模型适配器在 `provider_registry.py` 注册，绿色包从注册表生成桌面配置清单。适配器处理客户端、回合和用量回执，游戏运行时负责存档、任务和控制权；`desktop_api.py` 负责本地 HTTP，`desktop_runtime.py` 承接桌面指令。

2026-11-20 使用隔离单人存档验证工作管理、历史分页、伙伴设置、记忆编辑与旧数据导入。移开原安装目录后，使用模拟 Pi 成功打开导入的原会话并取得原生导航回执。真实模型长时游玩、执行中的农活改派和三组固定伙伴实机回归尚未验收。

2026-11-20 收尾验证通过 Python 全量测试（1635 项通过、2 项跳过）、Ruff、桌面和 Mod 构建、Transport 测试及伙伴服务断线恢复隔离实机。正式 mcode 三组回归仍需已登录的本地 mcode 客户端。

本机 dsh 和 Codex 已验证随桌面启动并连接隔离存档，未发起模型请求。模拟 MiniMax Code 已验证列出会话、核对并接续所选会话、收发消息、断开及玩家接管；真实 MiniMax Code 会话与在线模型仍待验收。

本批用隔离存档和模拟 Pi 验证计划采纳、暂缓、事项关闭与恢复，以及实时提醒、分页和已读持久化。真实模型下的节日准备和跨日节点核实尚未实机验收。
