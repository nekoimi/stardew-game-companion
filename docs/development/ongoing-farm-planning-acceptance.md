# 持续经营规划与接续验收

更新日期：2026 年 11 月 25 日。

## 现场原因

安装包日志中的最近回合完成了收获、浇水和补水，但没有使用阶段执行；随后的自主回合只查询状态、更新目标并总结明日计划，没有原生动作。长期经营要求被每日总结覆盖，较新的扩展授权只存在于滚动聊天历史中；没有动作的收尾又无法产生下一次工作唤醒，形成有体力但不再工作的状态。

本次只读取玩家安装目录的日志和数据库。所有实机验证使用复制存档、隔离 Mod 和运行时，未改动玩家安装包、配置和存档。

## 实现

- 玩家明确提出持续经营时，运行时直接绑定持续目标；原始要求、后续玩家要求、当天重点和进度分开保存。模型日结不再改写长期目标，追加要求不会随聊天摘要滚出上下文。
- `manage_arrangements` 增加 `set_day_plan`，在现有目标内保存当天重点、下一步、替代方向及局部受阻证据。没有持久化动作队列，也没有增加模型工具入口；八个工具继续共用观察、聊天和原生执行链路。
- 模型结束持续工作回合前，检查是否记录了当天有效等待条件。缺少下一步时要求重新评估资源并实际执行；连续两次提醒后仍只有总结则明确记录规划异常，保留目标，避免自动刷总结耗费 Token。
- 等待前需评估当天替代工作，已到达的时间、次日或农田变化条件不能继续当作等待理由；过夜重新规划。有限任务仍可正常完成，插件指令继续使用独立的现有边界。
- 桌面「农场工作」展开目标可查看重点、下一步、受阻事项及规划异常。F8 新要求在工具边界接入，F9 接管后不触发接续检查或自动夺回控制权。
- 正式模型验证额外发现：伙伴斜走后的小数坐标在障碍旁对齐时，碰撞探测对已经取整的包围盒再次叠加负小数，误差一像素造成卡住。移动现在按目标位置的原生取整规则计算包围盒；仍执行原生碰撞检查。

`.test-runs/presets-1125-122543-b931-game` 的模拟 API 运行通过。模拟模型故意在照料结束后先总结，只有正式运行时发出接续检查才继续采木与收纳；证明检查能阻止提前收尾，不代表正式模型决策质量。

## 范围与限制

本次解决长期要求丢失和日常后提前收尾，不保证模型在任意存档都能制定最优经营策略。等待仍依赖模型对已观察资源与授权的判断；规划持续失败会明确提示调整要求或模型，不通过后台无限重试掩盖问题。不强制耗尽体力，不扩大玩家授权，不把单次路线失败当作整座农场永久不可经营。
