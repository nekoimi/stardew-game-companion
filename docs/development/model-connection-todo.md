## 阶段 0 · 契约、目录和配置兼容

- [x] **MODEL-01，定义配置与服务商目录。** 在运行时定义官方 OpenAI、官方 DeepSeek 和自定义接口，固定官方协议和默认模型。为自定义接口定义协议、Base URL、模型 ID 和流式选择，保持桌面接口统一。
  - 验收要求包括非法字段与组合可诊断，两个官方预设都能从目录读出默认模型，目录能进入绿色包。旧版缺省流式选项时按开启处理。
- [x] **MODEL-02，验证现有设置与凭据。** 记录现行官方和第三方 Responses 配置样例。将旧 `openai-compatible` 映射到自定义 Responses，保留端点、模型和可用凭据。
  - 验收要求包括旧设置可读、同地址沿用原 Key、换地址只能读取新地址对应凭据。桌面设置文件与诊断可用测试替身检查密钥泄露，测试结果不记录真实 Key。

阶段 0 验证通过 25 项 TypeScript 测试与 WPF Release 构建。随包 Node 生成的模型目录包含三个入口及两个官方默认模型。Windows 凭据测试用旧版 JSON 和临时凭据验证了地址复用、端点隔离和磁盘设置无 Key，并清理了测试凭据。

## 阶段 1 · 请求实现与 Agent 回合

- [x] **MODEL-03，接通自定义 Chat Completions 和 Responses。** 复用已验证的流式适配逻辑，补齐自定义 Chat Completions，增加两个协议的完整 JSON 响应路径。统一地址处理、工具关联、结束原因、用量和错误分类。
  - 验收要求覆盖两种协议各自的 `stream: true` 与 `stream: false`，检查实际路由、请求体、分段或完整响应解析和工具结果的再次提交。覆盖地址路径前缀及尾部斜杠、网关拒绝所选方式和工具参数无效。
- [x] **MODEL-04，对齐等待、取消和连接测试。** 将两种响应方式接入同一 Agent 回合。明确流式空闲超时、非流式单次等待预算和桌面连接检测预算，沿用控制权、改派与回执核对。按配置测试完整工具往返。
  - 验收要求包括可中断的非流式等待、迟到模型回复被丢弃、流式半截工具参数无法派工、开关不会自行切换。覆盖模型只回文本、无法理解工具回执及缺失用量的反馈。

阶段 1 的 28 项 TypeScript 测试通过。四种组合均核对了实际请求、端点路径、完整工具往返和调用 ID。覆盖非流式读到半截后取消、流式工具调用中断、拒绝流式及无效参数。桌面 Release 构建通过。

## 阶段 2 · 桌面设置页

- [x] **MODEL-05，拆分设置子 Tab。** 保留左侧「设置」，顶部横排「游戏启动」「模型连接」「存档偏好」，在 Tab 栏下方加横线。游戏启动页放目录和游玩方式。模型连接页保留官方默认模型、手填模型 ID 和高级流式设置，自定义接口展开协议、Base URL、模型 ID、Key 和流式开关。存档偏好在读档前显示「进入存档后可编辑」。
  - 验收时从首次打开的「游戏启动」切换到另外两页，核对键盘导航、焦点和窄窗口滚动。在各页填写草稿后往返切换，确认输入仍在。用两个隔离存档核对偏好按存档加载。切换服务商、端点或模型后，字段、凭据状态和反馈对应当前选择。
- [x] **MODEL-06，贯通独立保存、错误跳转和游戏内应用。** 各子 Tab 就地保存和反馈。模型连接页提供「测试连接」「保存模型设置」及空闲时的「应用模型」。启动检查发现目录有误或模型未配齐时，切到相应子 Tab，滚动并聚焦首个出错字段。连接测试、启动和应用模型沿用统一配置校验与「等待模型响应」状态。
  - 验收时用缺少模型 Key 的配置单独保存启动设置，然后点击启动，确认跳到模型连接并聚焦 Key。测试模型后保存并重启，确认配置恢复，测试操作本身只反馈结果。保存任一页时，其他页草稿仍在且原有已保存值保持。读档后在空闲时应用模型，核对同一存档的历史和目标。非流式等待时游戏画面和操作正常，F9 接管后玩家保持控制权。

阶段 2 用绿色样机完成了键盘切换、窄窗口检查、未读档提示、跨页草稿、启动校验定位、独立保存和重启恢复。用模拟服务在同一存档从 DeepSeek 非流式切到 OpenAI 流式，并在两个隔离存档之间核对偏好。实体 F9 在非流式等待期间终止回合并交还控制权。桌面运行目录为 `desktop-1121-223616-4e2a`。
