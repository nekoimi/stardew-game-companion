# 地图导航优化与验收

目标是让模型指定目的和必要约束，由程序完成入口选择、跨图、交互站位、连续步行和有界受阻恢复；仍使用八个工具入口，不新增持久化动作队列。精确站立、相邻交互和跨图触发分别验证，规划和执行共用原生碰撞规则。

## 实施任务

- [x] 入口图启发式与延迟精算，避免无关出口的全图搜索；复用已计算路段。
- [x] 有界路径缓存，复用前检查路段碰撞、动态占位和触发点；不持久化不可达结论，读档重建运行对象。
- [x] 区分精确站立、相邻交互、商店柜台等目标，模型不再选择每一张中间地图和操作站位；补水/休息沿用已有动作的站位管理。
- [x] 门、踩踏出口、地图边界分别执行原生过渡，核对实际新地图与落点，不以附近到达代替。
- [x] 连续直走和斜走，等价步长时优先减少转弯，保持原生碰撞和交互精度；不增加随机绕路。
- [x] 临时受阻短等、局部重算、替换入口；同状态有界恢复，取消、暂停与 F9 随时生效，不擅自清障。
- [x] 桌面区分规划、行走、跨图与受阻恢复，并提供结构化耗时、搜索和缓存证据。
- [x] 单元验证实际失败边界、TypeScript/C# 契约和固定伙伴回归；隔离实机验证家中到商店柜台、购种并返回农场。
- [x] 验证发行包，更新 README、使用说明和实际加载提示词，记录性能与未通过项。

## 验收标准

跨图导航内部零模型请求，真实地图变化确认每次过渡；新增障碍不能穿过，移除障碍允许恢复，营业限制与事件不能绕过。规划每帧保持毫秒级协作预算，常见路线争取 1 秒内开始执行，缓存路线争取 100 毫秒级；性能是需以实测证明的目标，不用缩短超时冒充优化。

自然语言经营验收与原生导航验收分别记录，模拟服务不证明模型自主决策。游戏使用测试包与隔离存档，日常安装和存档不改写；画面移动、碰撞、动作结果分别留证。

实现与证据见[导航验收报告](navigation-acceptance.md)，字段见[导航契约](../../contracts/game-bridge/navigation.md)。常见路线首次可行路段已在 1 秒内就绪；缓存搜索约 4 毫秒，但动作就绪含分帧调度约 234～241 毫秒，不能宣称端到端 100 毫秒。冷启动单次搜索切片约 21 毫秒，协作预算不是原生调用/JIT 的严格耗时上限。
