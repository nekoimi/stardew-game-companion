# 桌面插件平台实施 TODO

本清单对应[桌面插件中心与第三方服务托管方案](desktop-plugin-platform-plan.md)。首版交付通用的本地插件平台，覆盖 GUI 安装、启停、自动启动开关、插件设置入口、消息、事件订阅和 Agent 指令。首版用通用参考插件验收。直播和 Live2D 仅为架构示例，不纳入实施和验收。

按任务依赖实施。每批验收后记录提交、验证命令、测试结果和未覆盖项，再勾选任务。下列目录和接口是拟新增的交付物。

## 阶段 0 · 冻结 v1 契约

- [x] **PLUGIN-01　定义插件包与启动契约**
  - 交付 `contracts/plugin-host/` 下的清单 Schema、文件清单与共享样例。约定插件 ID、版本和兼容范围、Windows x64 入口、参数数组、工作目录、可选的 `settings.kind: "local-web"`以及包内哈希覆盖范围。
  - 验收时用同一份样例核对包结构、入口约束和协议版本。至少提供一个最小合法包样例与不兼容版本、路径越界等拒绝样例。
- [x] **PLUGIN-02　定义生命周期和消息契约**（依赖 PLUGIN-01）
  - 交付启动环境、`hello`、`heartbeat`、停止指示、运行实例身份及鉴权规则。定义消息、快照、SSE、指令提交和查询的字段、状态码与重试语义。已启用的运行实例默认拥有公开插件接口的全部权限。
  - 验收时共享样例覆盖设置页登记、待配置、需重启、运行凭据失效、断线续读、忙碌和指令回执。兼容规则明确新增可选字段与未知事件的处理。
- [x] **PLUGIN-03　确定 Agent 接入策略与记录归属**（依赖 PLUGIN-02）
  - 建议首版只在空闲且玩家已有目标无可执行工作时接收外部指令，为每条指令分配独立目标。忙碌时由插件决定何时重试。跨回合或跨日的外部任务先返回待玩家处理，后续工作由玩家明确确认后按普通目标接续。玩家保有暂停、打断和接管。
  - 建议由运行时 SQLite 统一保存已接收指令与结算状态，键包含安装实例、插件 ID 和插件的请求 ID，记录原游戏会话、内容指纹及内部关联编号。宿主重连时按原编号查询。
  - 验收时写出状态转换和受理条件，覆盖相同编号重试、编号冲突、接收后响应丢失、旧会话查询、部分完成及结果待核对。分别定义回合结束、目标达成与原生完成数量。将结论写入 v1 契约。

阶段记录见本次「define desktop plugin host v1 contract」提交。使用开发依赖 `jsonschema` 运行 `python tests/contracts/check-plugin-contract.py`，清单 Schema、共享文件哈希、不兼容版本与路径越界样例通过。握手、SSE 与原生执行联调分别在阶段 1 至阶段 3 验证。

## 阶段 1 · 桌面插件宿主与设置入口

- [x] **PLUGIN-04　实现本地安装与插件注册**（依赖 PLUGIN-01）
  - 在 `apps/desktop/` 内拆出独立于 WPF 的安装与注册服务。安装到版本目录，配置、启用状态和自动启动偏好独立于版本目录持久化。ZIP 先解压到临时目录，校验路径、文件及哈希后才切换安装记录。初次安装默认禁用，首版提供本地安装、卸载和保留插件数据的选项。
  - 验收时覆盖文件损坏、路径越界、不兼容包和安装中断。失败后原安装仍然可用，插件数据按用户选择处理。
- [x] **PLUGIN-05　实现独立的进程生命周期**（依赖 PLUGIN-02、PLUGIN-04）
  - 沿用桌面进程启动经验，为同一绿色包目录建立独立于游戏会话的宿主租约。按清单用参数数组直接启动可执行文件，将本机地址、插件数据目录和本次运行凭据传入子进程。用 Windows Job Object 跟踪宿主拥有的进程树，处理并发启停、崩溃退避、退出回收及日志。通过模拟握手与心跳先验证进程管理。 [桌面进程](../../apps/desktop/src/DesktopProcesses.cs)
  - 验收时覆盖游戏尚未启动、重复点击启动、第二个桌面实例、托盘运行、启动超时、意外崩溃与优雅停止超时。插件退出只影响宿主拥有的对应进程。
- [x] **PLUGIN-06　实现本机接口、握手与运行实例鉴权**（依赖 PLUGIN-02、PLUGIN-05）
  - 监听本机随机端口。实现握手、心跳、每次运行独立凭据与校验，区分进程运行、协议已连通、待配置和业务就绪。停止时先关闭该运行实例的业务接口，再通过心跳下发停止指示。部署宿主接口时一起验证请求大小、速率和并发订阅上限。
  - 验收时覆盖凭据过期、运行实例替换、停用和版本不兼容。验证无效凭据无法读写，已启用的就绪实例可以使用公开接口。采用方案给出的启动与停止时间作为联调默认值，记录实测结果。
- [x] **PLUGIN-07　实现 WPF 插件页与配置入口**（依赖 PLUGIN-04 至 PLUGIN-06）
  - 在侧边导航新增「插件中心」，列表及详情展示来源、版本、启停和可操作错误。「随伴侣程序自动启动」使用开关，由 GUI 按插件保存。业务设置按当前运行实例在握手登记的本机地址用系统浏览器打开，页面、验证和配置生效由插件负责。
  - 验收时覆盖切换自动启动开关、直接启用、首次待配置、停服后启动并打开设置、设置页不可用、热加载和需重启提示。用测试插件验证待配置期间可打开页面，重启后打开新实例登记的地址。运行实例鉴权纳入 PLUGIN-06，完整指令闭环纳入 PLUGIN-12。日志沿用桌面现有诊断目录入口。

阶段记录见本次「add desktop plugin center and process host」提交。`pwsh -File tests/desktop-plugins/run.ps1 -DotNet <.NET 10 SDK>` 通过，覆盖取消安装、损坏与不兼容包、目录越界、重复启用、第二实例、15 秒握手超时、10 秒停止宽限、配置状态、地址回环校验、凭据替换和工作进程回收。发布 WPF 后用 Windows UI Automation 验证插件页、直接启用、自动启动开关持久化、托盘隐藏与恢复及插件随桌面退出。游戏侧通信和完整绿色包验收安排在后续阶段。

## 阶段 2 · 通用通信与 Agent 闭环

- [ ] **PLUGIN-08　实现插件消息和面向插件的状态投影**（依赖 PLUGIN-02、PLUGIN-06）
  - 接收通用状态、通知和插件命名空间事件。对游戏状态、Agent 状态、动作终态和公开回复按公开契约生成稳定字段。需要的新数据从运行时观察或 Mod 回执补齐，日志保留来源与关联编号。
  - 验收时用同一宿主接收两种任意业务负载，通用消息只按声明展示或记录。核对公开回复为玩家可见的完整消息，确认凭据、提示词、历史对话和原始世界快照未进入插件输出。
- [ ] **PLUGIN-09　实现快照和 SSE 订阅**（依赖 PLUGIN-08）
  - 快照和游标在同一状态边界取得，事件按会话和事件 ID 关联。提供有限续读窗口，维护有界订阅缓冲，处理慢消费者、插件停止和切换存档。
  - 验收时覆盖快照到订阅间的状态变化、并发订阅、断线续读、游标过期及重复公开回复。订阅示例按消息 ID 去重，切换存档时清空旧会话的展示状态。
- [ ] **PLUGIN-10　接入插件指令与独立回合**（依赖 PLUGIN-03、PLUGIN-06）
  - 在桌面宿主转交自然语言与可信来源。在 `apps/runtime/` 接入独立回合的受理策略，复用现有回合和原生执行链路。受理在运行时原子检查忙碌、插件运行状态、会话与控制权，游戏工具执行时仍检查原有门槛。GUI 显示插件来源，玩家控制操作沿用当前入口。
  - 验收时覆盖同时提交、已有玩家目标、待确认事项、休息或跨日、暂停、F9 接管以及切换存档。玩家原目标和历史关联按原语义保留。旧动作终态未确认时先核对。 [回合执行器](../../apps/runtime/src/application/turn-runner.ts)
- [ ] **PLUGIN-11　实现幂等、结果查询与故障恢复**（依赖 PLUGIN-10）
  - 在运行时关联插件请求、回合、目标和原生回执。按契约返回已接受、运行中、等待确认、部分完成、结束及待核对状态。查询按插件身份隔离，终态未知时沿用原生回执核对流程。
  - 验收时用相同请求重试，验证只执行一次。覆盖响应丢失、运行时与宿主分别重启、存档切换后回查、停用时取消并结算，以及单纯掉线后查询正常结果。目标完成量只取已确认回执。 [桌面 API](../../contracts/desktop-api/v2.md) · [运行时存储](../../apps/runtime/src/adapters/storage/companion-store.ts)

## 阶段 3 · 首版验证与交付

- [ ] **PLUGIN-12　提供两种语言的参考插件与模拟宿主**（依赖 PLUGIN-02，完整联调依赖 PLUGIN-07、PLUGIN-09、PLUGIN-11）
  - 提供可独立打包的两个 Windows x64 示例，建议使用 Go 与自包含 C#。一个提交自然语言并查询回执，另一个订阅并展示状态、已确认的动作结果和 Agent 公开回复。两者复用同一清单、生命周期接口和联调样例。至少一个示例带独立设置页。
  - 验收时从本地 ZIP 安装两个示例，用同一桌面构建同时运行。核对订阅插件展示的结果与宿主事件一致，并验证指令查询只能访问提交插件自己的记录。使用模拟宿主验证插件能独立开发和联调。
- [ ] **PLUGIN-13　验证绿色包与现有行为**（依赖 PLUGIN-12）
  - 从干净源码构建并校验 Windows 绿色包，用含中文和空格的目录解压。跑受影响的 WPF、TypeScript 和 C# 测试，使用隔离存档、模拟模型和两个示例插件跑端到端闭环。同步首页、使用指南、契约索引和实际加载的提示词。
  - 验收记录包含提交、包 SHA256、插件版本、测试结果和未执行项。覆盖普通聊天、现有目标续作、改派、F9 与退出流程。插件启动和退出与现有游戏生命周期分别核对。真实游玩证据保留在本地。 [构建说明](../../CONTRIBUTING.md) · [隔离实机回归](../repeatable-companion-acceptance.md)
