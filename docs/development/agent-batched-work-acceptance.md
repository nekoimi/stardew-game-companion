## 实现与证据

八个模型工具入口保持不变，`submit_work` 新增 `tend_crops`、`harvest_crops`、`collect_ground_items`、`store_items` 和 `ship_inventory`。运行时按最新观察逐项派发原生动作、核对终态，动作及世界状态未知时停止后续派工。入箱阶段当前仅核对农场箱子，其他地点继续使用原有单动作接口。

阶段状态只在当前回合内存在。现有目标的 `lastStage` 保存成果摘要与回执索引；原始子动作仍使用既有动作记录。等待支持次日、约定时间和农田变化；时钟、移动和逐条阶段回执不会产生重复规划。

## 同场景模拟 API 对比

协议均为流式 DeepSeek Chat Completions、`deepseek-flash`，存档来源相同。模拟服务发出工具请求，原生动作、碰撞、动画和成果均由正式 Mod 验证。基线见[基线记录](agent-batched-work-baseline.md)。

| 场景 | 基线模型请求 | 候选模型请求 | 基线 / 候选原生动作 | 基线 / 候选场景总耗时 | 结果 |
| --- | ---: | ---: | ---: | ---: | --- |
| care-guidance | 6 | 5 | 2 / 3 | 39.7 / 22.4 秒 | 12 株浇完，补水续浇，追加消息在边界接入 |
| harvest-logistics | 9 | 9 | 4 / 4 | 28.0 / 21.9 秒 | 收获入箱、取出出货、木材保留 |
| rest-forestry | 11 | 11 | 5 / 10 | 100.5 / 89.0 秒 | 休息到 80、砍两棵成熟树、保留幼树并入箱 |

最终模拟运行目录为 `.test-runs/presets-1125-012256-07fa-game`，同一实例连续五组通过。新增 `water-refill` 用 3 次模型请求和 3 个原生动作完成 12 株照料，阶段内新增模型请求为 0；`empty-farm` 的三类阶段均返回无目标，原生派工次数为 0。

采木后的拾取阶段每次重新观察地面，部分物品在走近过程中自动入包，出现六条 `no-item` 原生回执；这是已确认终态，阶段通过背包增量核对收集，未重放旧动作。原生动作数因此增加，本次不声称所有任务的动作数或 Token 均下降。场景总耗时含布置与采样，不能作为模型延迟或游戏帧率；单次运行也不足以建立统计性能结论。

65 格确定性收获回归使用三批原生动作，只需派工和汇报两次模型调用，阶段摘要小于 1,500 字符。常规小任务原本已能单动作处理，因此其模型请求数未必降低。

## GUI 与正式模型

`.test-runs/desktop-1125-003049-cbeb` 的 GUI 隔离控制回归通过：思考中 F9、行走中 F9、打断改派、所属运行时断线后核对旧动作、原生睡觉及次日同目标接续。

第三方 Responses、`gpt-6.1-sol`、流式正式 API 在 `.test-runs/presets-1125-003952-2121-game` 通过 `water-refill`：模型主动调用照料阶段，12 株浇完，阶段三动作之间模型请求为 0，整个回合 4 次模型请求，任务执行 32.5 秒。

随后固定三组正式运行 `.test-runs/presets-1125-005141-6ec6-game`：照料和采木通过，收获物流遗漏任务开始前已被自动吸入背包的 3 份木材。保留该失败报告；针对性修复在收获与拾取阶段摘要同时提供当前背包物品和当次增量，提示词明确地面为空不能代替收纳完成。

修复后正式 `harvest-logistics` 于 `.test-runs/presets-1125-011915-186a-game` 复测通过：5 份防风草收获入箱、再取出出货，3 份木材留在箱内，背包无遗漏，碰撞与行走动画检查通过。场景总耗时 151.4 秒，首轮工作 75.1 秒；包含真实网络与模型决策等待，不与模拟服务耗时混用。

本机临时配置的 DeepSeek 官方凭据在连接检查返回 `authentication`，运行目录 `.test-runs/presets-1125-003406-4cf8-game`，未执行正式游戏任务。没有官方 OpenAI 凭据；这两家正式调用不能标记通过。正式模型未采集改造前的同模型基线，因此不作正式 API Token 节省百分比承诺。

## 日志与后续范围

`work_stage_completed` 记录阶段编号、类型、目标数量、原生派工数、阶段内模型请求、成果、停止原因与耗时；`turn_completed` 记录整轮模型请求、动作和阶段总量。两者通过回合、原要求及目标编号关联，不包含玩家指令正文、API Key 或完整模型请求。
