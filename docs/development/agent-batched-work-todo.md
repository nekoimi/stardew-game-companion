## A. 基线与故障场景

- [x] **BW-01，采集当前模型往返基线。** 使用固定目标记录模型请求数、动作数、总耗时、工具失败、未知终态与最终状态。[基线记录](agent-batched-work-baseline.md)
  - 验收：同一模拟模型、隔离存档、固定场景可重复对比，报告标明模拟或正式 API。
- [x] **BW-02，新增无有效目标回归。** 覆盖无缺水作物、无成熟作物、无掉落物时不得发起相应原生动作。
  - 验收：断言动作调用计数为零，并检查 Agent 汇报“没有目标”而非虚报完成。
- [x] **BW-03，固化阶段中断边界用例。** 覆盖 F9、F8 新要求、暂停、读档、休息时间和动作终态未知。
  - 验收：断言中断/未知动作后不会派发阶段内下一动作；F9 后不自动夺回控制权。

## B. 运行时批次执行

- [x] **BW-04，定义 `submit_work` 农田照料操作。** 明确农区、目标范围、参数和阶段结果字段。其他工作流在首个贯通场景通过后按相同方式扩展。
  - 验收：模型工具清单仍固定为八个入口；阶段只能调用白名单操作，参数经过现有 schema 和目标绑定检查。
- [x] **BW-05，实现阶段内即时执行器。** 复用 `TurnRunner`、`CompanionTools` 与原生动作链。每个动作独立登记、执行、结算和复查；阶段状态仅在当前回合内存活。
  - 验收：动作顺序执行，无后台长队列；每个子动作均可由既有回执查询和审计追踪。
- [x] **BW-06，实现工作流停止规则和结果摘要。** 区分完整观察下无目标、部分观察、单项失败、无进展与未知终态。单次目标上限只用于分批，长时间无响应时先核对状态。
  - 验收：所有停止结果含已完成、剩余/跳过、失败原因与是否需要核对，不把未知转换成零产出或成功。
- [x] **BW-07，接入控制权和玩家消息。** 阶段动作边界校验取消、F9、暂停、存档/会话绑定、休息计划及追加要求。
  - 验收：旧阶段不能覆盖新要求，不会在控制权转给玩家后继续派工。
- [x] **BW-08，覆盖重复执行与恢复。** 注入动作超时、迟到回执、进程重连和重复模型请求。
  - 验收：终态未知先核对；已结算动作不重复执行；状态不变的同批操作有明确停止上限。

阶段 B 通过 57 项运行时测试、693 项 Mod 测试、63 项传输测试、7 项实机脚本测试和 11,447 项发行文件清单校验。模拟 API 的固定三组均通过，其中 `rest-forestry` 的连续组运行在重置布置时超时，单组复测通过。证据位于 `.test-runs/presets-1124-230719-609a-game` 和 `.test-runs/presets-1124-231017-7575-game`。

## C. 第一批农场工作流

- [x] **BW-09，批量农田照料。** 按当前观察处理缺水作物，按需补水后重查剩余地块。
  - 验收：从首次浇水到补水和续浇之间新增模型请求数为零。每批后核对作物状态和水量，空地、旧坐标和观察不完整分别覆盖。
  - 阶段 B 使用流式模拟 DeepSeek Chat Completions。`water-refill` 完成 12 株，浇水、补水与续浇共 3 个原生动作，18.8 秒。模型仅在初始观察前、派工前与汇报前被调用，共 3 次。`care-guidance` 完成 12 株，追加消息在动作边界送达，共 3 个原生动作、5 次模型请求、25.3 秒。证据位于 `.test-runs/presets-1124-230416-a35b-game`。
- [x] **BW-10，批量成熟作物收获。** 对实际成熟目标分批收割并核对背包与地面掉落。
  - 验收：复生作物和多产掉落按真实状态核对；背包容量不足时停下整理，不报告虚假产量。
- [x] **BW-11，批量拾取观察到的物品。** 限定伙伴所有权、有效观察和当前可达目标。
  - 验收：不把障碍、放置物、已经吸入背包的产物当作掉落；无有效物品不调用原生拾取。
- [x] **BW-12，批量收纳与出货。** 基于玩家要求和实际背包/箱子状态处理目标物品。
  - 验收：每类转移核对真实库存差分；保留规则、背包空间和物品数量正确。

阶段 C：62 项运行时测试通过，覆盖多产收获、背包满、拾取途中自动吸取、出货保留量、库存不符和观察中断。绿色候选包通过 11,447 项文件清单校验，流式模拟 API 的 `harvest-logistics` 与 `rest-forestry` 隔离实机通过（38.2 / 95.4 秒），分别位于 `.test-runs/presets-1124-232330-83bc-game` 与 `.test-runs/presets-1124-233602-d010-game`。入箱工作阶段目前核对农场箱子；其他地点保留单动作接口。

## D. 阶段规划与提示词

- [x] **BW-13，按阶段结果推进和接续目标。** 工作流内置完成、等待与停止规则。按新游戏日、相关观察变化、游戏时间条件或玩家要求接续。
  - 验收：批次内每条成功回执不会各自触发一次规划。同一状态下，日常照料完成后进入适当的等待状态，下一天从实际观察续作。
- [x] **BW-14，调整运行时提示词。** 指导模型以阶段为单位规划、读取阶段摘要续作，并在偏差和决策点重新判断。
  - 验收：同步首页、使用说明和实际加载提示词中受影响的说明；禁止无有效目标动作的约束在执行层也成立。
- [x] **BW-15，控制上下文与摘要体积。** 给模型返回完成摘要、证据、剩余目标和停止原因，不重复展开全部逐格日志。
  - 验收：模型可据摘要正确决定续作/调整/完成；原始动作证据仍可在历史与诊断中追溯。

阶段 D：阶段摘要写入现有目标 `lastStage`，不创建工单；`when_farm_changes` 只按作物变化唤醒，可与次日或游戏时间条件并用。回归确认 65 格收获分 3 个原生动作、仅 2 次模型调用，摘要小于 1,500 字符；每条子动作回执仍保留在历史中，时钟、移动和阶段回执均不产生重复规划。

## E. 度量、集成与发行

- [x] **BW-16，记录批次效率诊断。** 记录模型请求数、执行动作数、目标数、成果、停止原因与耗时。

- [x] **BW-17，跑 TypeScript 与契约回归。** 验证无目标、异常、中断和继续工作的规则，检查真实观察及回执的跨语言字段。
  - 验收：原生派工次数、模型请求次数与控制状态均可断言，共用现有契约样本。
- [x] **BW-18，执行隔离实机回归。** 先用模拟 API 运行固定三组与新增农事边界，再用可用的正式 API 检查规划和连续执行体验。
  - 验收：分别记录结果及未执行项。独立核对动作结果、移动碰撞和动画变化，并检查休息、玩家接管和次日接续。
- [x] **BW-19，评估产品体验改善。** 对比同一模型、协议、流式设置和场景的请求数、耗时、失败率、最终状态。
  - 验收：可靠性不下降且请求数或耗时有实际改善；未达标则调整批次边界，不以模型自述替代证据。
- [x] **BW-20，验证构建与更新文档。** 执行 TypeScript、C#、跨语言契约、发行包及提示词/使用说明检查。
  - 验收：新包可按唯一启动入口运行，验收未执行项如实记录。
