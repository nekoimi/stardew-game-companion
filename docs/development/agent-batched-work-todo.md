## B. 运行时批次执行

- [ ] **BW-04，定义 `submit_work` 农田照料操作。** 明确农区、目标范围、参数和阶段结果字段。其他工作流在首个贯通场景通过后按相同方式扩展。
  - 验收：模型工具清单仍固定为八个入口；阶段只能调用白名单操作，参数经过现有 schema 和目标绑定检查。
- [ ] **BW-05，实现阶段内即时执行器。** 复用 `TurnRunner`、`CompanionTools` 与原生动作链。每个动作独立登记、执行、结算和复查；阶段状态仅在当前回合内存活。
  - 验收：动作顺序执行，无后台长队列；每个子动作均可由既有回执查询和审计追踪。
- [ ] **BW-06，实现工作流停止规则和结果摘要。** 区分完整观察下无目标、部分观察、单项失败、无进展与未知终态。单次目标上限只用于分批，长时间无响应时先核对状态。
  - 验收：所有停止结果含已完成、剩余/跳过、失败原因与是否需要核对，不把未知转换成零产出或成功。
- [ ] **BW-07，接入控制权和玩家消息。** 阶段动作边界校验取消、F9、暂停、存档/会话绑定、休息计划及追加要求。
  - 验收：旧阶段不能覆盖新要求，不会在控制权转给玩家后继续派工。
- [ ] **BW-08，覆盖重复执行与恢复。** 注入动作超时、迟到回执、进程重连和重复模型请求。
  - 验收：终态未知先核对；已结算动作不重复执行；状态不变的同批操作有明确停止上限。

## C. 第一批农场工作流

- [ ] **BW-09，批量农田照料。** 按当前观察处理缺水作物，按需补水后重查剩余地块。
  - 验收：从首次浇水到补水和续浇之间新增模型请求数为零。每批后核对作物状态和水量，空地、旧坐标和观察不完整分别覆盖。
- [ ] **BW-10，批量成熟作物收获。** 对实际成熟目标分批收割并核对背包与地面掉落。
  - 验收：复生作物和多产掉落按真实状态核对；背包容量不足时停下整理，不报告虚假产量。
- [ ] **BW-11，批量拾取观察到的物品。** 限定伙伴所有权、有效观察和当前可达目标。
  - 验收：不把障碍、放置物、已经吸入背包的产物当作掉落；无有效物品不调用原生拾取。
- [ ] **BW-12，批量收纳与出货。** 基于玩家要求和实际背包/箱子状态处理目标物品。
  - 验收：每类转移核对真实库存差分；保留规则、背包空间和物品数量正确。

## D. 阶段规划与提示词

- [ ] **BW-13，按阶段结果推进和接续目标。** 工作流内置完成、等待与停止规则。按新游戏日、相关观察变化、游戏时间条件或玩家要求接续。
  - 验收：批次内每条成功回执不会各自触发一次规划。同一状态下，日常照料完成后进入适当的等待状态，下一天从实际观察续作。
- [ ] **BW-14，调整运行时提示词。** 指导模型以阶段为单位规划、读取阶段摘要续作，并在偏差和决策点重新判断。
  - 验收：同步首页、使用说明和实际加载提示词中受影响的说明；禁止无有效目标动作的约束在执行层也成立。
- [ ] **BW-15，控制上下文与摘要体积。** 给模型返回完成摘要、证据、剩余目标和停止原因，不重复展开全部逐格日志。
  - 验收：模型可据摘要正确决定续作/调整/完成；原始动作证据仍可在历史与诊断中追溯。
