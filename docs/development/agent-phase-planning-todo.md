## A. 基线与契约设计

- [x] **PP-01，采集当前完整阶段基线。** 固定隔离存档、自然语言目标、模型/协议/流式设置，记录采木入库、补水续浇、收获物流的模型请求、观察、原生动作、等待时间和成果。
  - 验收：覆盖当前多坐标 `chop_tree` 能力，保留正式模型实际行为与确定性模拟两种证据；成功、失败和缓存冷/热分别记录。
- [x] **PP-02，定义集中观察与阶段计划契约。** 明确观察引用、完整性、目标量语义、成果、资源边界、步骤依赖、枚举分支、结果引用和摘要字段。
  - 验收：八个具名工具不变；计划通过 `submit_work.execute_phase` 提交；存档、角色、会话、目标和玩家要求版本由程序绑定。首版最多 8 个语义步骤、4 个例外分支，无脚本和持久化动作队列。
- [x] **PP-03，固化必须保留的故障边界。** 在现有测试基础上增加阶段内 F8/F9、过期观察、背包满、保护对象、部分成果与未知终态用例。
  - 验收：真实故障与行为边界有可失败断言，不重复验证简单赋值；旧阶段不能覆盖新要求，未知回执不等于零产出。

进入 B 的条件：基线可重复，计划与观察字段、授权及控制边界已明确。

## B. 全图观察与缓存

- [x] **PP-04，提供按实际地图边界的树木与水源观察。** 原生查询分批读取实体/地形，支持分页、扫描范围和完整性；不能用附近快照冒充全图。
  - 验收：远处成熟树可发现；自定义大地图水源可发现；截断、地图未加载和知识不可见分别标为未知。查询分帧执行，不阻塞游戏主线程，不后台读取可变原生对象。
- [x] **PP-05，集中准备规划观察包。** 按目标准备作物、树木、库存、箱子、水源、时间体力和路线候选摘要，运行时合并分页后再调用模型。
  - 验收：自然语言采木目标不需模型逐个查询才能凑齐必需信息；观察引用不能跨存档/角色模式/游戏会话使用；未知估计不被包装成确定收益。
- [x] **PP-06，实现地图基础与设施缓存。** 缓存水域、岸边、出口和发现过的箱子/床等设施，独立于角色记忆，损坏可丢弃重建。
  - 验收：以存档、地图、模式及内容指纹隔离；移动箱子、增减建筑、内容重载和读档失效有覆盖；指纹不确定时保守重查。持久化缓存复核后才参与执行，不保存动态掉落物或可自动恢复的计划。
- [x] **PP-07，接入补水缓存与程序内恢复。** 热查询优先有效岸边，使用前原生核验；失败换岸边或补查其他水源。
  - 验收：同地图连续补水完整扫描次数下降；缓存过期/岸边被挡/水源移除仍正确处理；候选耗尽明确停止；补满即结束，不遍历全部水源，不需要模型判断常规换点。

进入 C 的条件：原生观察有权威完整性，缓存冷/热与失效行为可验证，跨语言同一只读样本仅生成一次。

## C. 完整阶段执行器

- [x] **PP-08，实现计划校验和执行绑定。** 校验 schema、步骤依赖、结果引用、有限分支、操作白名单、资源语义、设施去向和观察新鲜度。
  - 验收：循环依赖、跨阶段伪造引用、扩大授权、保护规则冲突、未知操作及过期观察在派工前被拒绝；不信任模型自填的任务身份和成本。
- [x] **PP-09，实现当前回合内的 `PhaseExecutor`。** 通过共用回合执行器复用原生动作，解释阶段步骤、条件和程序生成的目标集合，不在 `TurnRunner` 继续堆叠所有业务逻辑。
  - 验收：每动作即时登记、执行、结算并观察；步骤之间正常执行期模型请求为 0；当前阶段可看见多种操作的完整依赖，禁止用固定单类批次替代整个阶段规划。
- [x] **PP-10，实现候选访问与采木成果控制。** 程序按交互站位路径成本、树组和资源边界选择目标；模型指定目标、范围和路线偏好。
  - 验收：达到木材目标/体力保留边界后不再选择新树；不假定单树固定产量；成熟树优先，幼树、果树和装采集器树受保护；旧路线不能穿过新增障碍。计算工作量有界，不为有进展任务设置固定总时长中断。
  - 参考故障回归：木材仍散落时先核对并收集，不能因背包暂未达标就多砍一批树；跨入箱子后的已确认阶段产量继续计入目标，不把背包变空当成进度清零。
- [x] **PP-11，贯通采伐、产物收集和入库。** 使用有类型的结果引用，顺路吸取与树组间收集结合，背包紧张按预设分支先入库。
  - 验收：一次模型请求输出完整计划后，至少完成多棵树采伐、真实产物核对和入箱；自动吸入、掉落移动、玩家收走、原有库存和随机产量不误算。不向模型逐条回传内部扫描与子动作。
- [x] **PP-12，实现局部失败分支和无进展退出。** 单点不可达换候选，备用设施仅在已授权时可用；无有效替代、资源用途改变等集中返回重规划原因。
  - 验收：同一目标/站位/地图状态下不盲目重复；旧动作停止且终态已确认后才派剩余工作；失败释放执行权，不后台重启旧导航。
- [x] **PP-13，贯通控制、消息和生命周期。** F8 新要求在原生边界终止未执行步骤；F9 取消；暂停恢复复查；作息、读档、跨日、重连与退出复用现有流程。
  - 验收：思考中和执行中接管均不自动夺回；追加要求不被旧阶段覆盖；未知终态先核对，已完成动作不重放；进程重启或跨日不恢复旧内存计划，按真实剩余量重规划。

进入 D 的条件：完整采木入库通过模拟实机，执行期零模型请求，控制边界和成果全部正确。

## D. 请求组织与集中反馈

- [x] **PP-14，拆分稳定规则与动态上下文。** 调整模型适配器组装，系统规则与工具顺序稳定；动态观察置于明确的数据消息边界，角色/约定按版本更新。
  - 验收：Chat Completions、Responses、流式与非流式契约正确；游戏状态不成为工具授权；连续同会话的已确认历史前缀保持一致，不每次重写动态系统段。切换模型保留角色与目标，按现有规则重建模型上下文。
- [x] **PP-15，复用已确认增量机制。** 阶段内部日志留在本地，结束只回传一次事实摘要；下一阶段附送达基线后的变化。
  - 验收：动作失败但请求已送达不重建全量；未确认送达不推进基线；首次会话、读档和主动压缩后重建。无额外模型摘要请求，无重复整图和逐格日志。
- [x] **PP-16，记录真实请求与缓存指标。** 区分规划、执行、汇报、重试、异常重规划；关联原生动作与本地缓存命中、供应商缓存用量。
  - 验收：供应商缺少缓存字段时记未知；本地扫描缓存不冒充供应商缓存；输入/输出/cacheRead/cacheWrite 口径清晰。日志继续过滤密钥、正文和完整地图。

进入 E 的条件：协议回归通过；正常完整阶段规划 1 次、执行期 0 次，必要的总结最多另 1 次，额外重试与重规划独立列明。

## E. 日常链路与桌面体验

- [x] **PP-17，将照料、收获、收集与入库纳入一次完整计划。** 复用已有农事工作流，以本阶段依赖决定顺序和产物流向，不写死全局经营优先级。
  - 验收：一份阶段计划覆盖补水续浇及收获物流，缺水/背包满采用事先允许的分支；空地不浇水，非成熟作物不收获，未授权库存不入库或出货。阶段完成后持续目标仍可安排下一项有意义工作。
- [x] **PP-18，接入现有 GUI 阶段状态。** 农场工作显示成果目标、当前步骤、确认成果和停止/重规划原因，Agent 状态区分规划、执行与核对。
  - 验收：内部扫描和坐标更新不刷屏，正常聊天及时显示；无新增游戏自定义弹窗；暂停、改派、接管沿用现有入口；未知成果不显示成功。
- [x] **PP-19，同步实际提示词与使用文档。** 说明模型应输出完整阶段、条件分支和资源边界；首页、玩家指南、契约与开发说明按真实能力更新。
  - 验收：工具名称与运行时一致，示例用自然语言；不宣称支持任意全天自动计划、百万窗口或必然缓存命中；旧批次验收保留历史含义。
