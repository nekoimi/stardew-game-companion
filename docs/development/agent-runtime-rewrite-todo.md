## 阶段 1 · 可玩的最小闭环

依赖 TS-01 至 TS-03。先支持一条指令、一项原生动作和一个真实模型。

- [ ] **TS-04，接入第一家模型。** 用 `pi-ai` 接入 DeepSeek 官方 API，把文本、工具调用、结束原因、用量和错误转换为项目事件。实现受控的 Key 读取和独立连通性测试。
  - 验收：有效配置完成文本与工具调用闭环。错误 Key、缺失模型、瞬时断流及缺失用量都有可辨识结果，日志和诊断中查不到 Key。
- [x] **TS-05，接通 WPF 和 SMAPI。** WPF 启动 TS 本地服务，发送自然语言并订阅状态。TS 绑定隔离游戏，从 Mod 获取观察，执行移动并核对回执。新增「模型」设置，含服务商、Key、模型和测试连接。
  - 验收：使用绿色样机，无全局 Node 和模型客户端。通过桌面从设置、启动、进入存档走到显示与当前指令匹配的原生移动回执。错误信息留在对应操作区域。
- [x] **TS-06，完成暂停、接管和改派。** 实现单角色单回合、原生动作单执行权、取消信号与动作终态核对。每次工具执行前校验回合和游戏会话，在工具边界传递玩家追加要求。
  - 验收：思考时和走路时都能按 F9 接管。旧模型响应无法重新派工。改派保留旧动作成果，回执丢失时查询游戏状态并暂停新动作，终态确认后才能继续。

## 阶段 2 · 迁移完整 Agent 功能

依赖 TS-04 至 TS-06。使用新数据格式恢复产品能力。

- [x] **TS-07，落地项目自有数据。** 新建 SQLite 库，按存档保存角色、记忆、对话、目标、安排、待确认事项和用量。落实普通回执和最终回复去重，贯通 GUI 设置、手记、历史和用量。
  - 验收：两个存档的数据互相隔离。重启后恢复同一角色、对话、未完成目标和待确认事项。失效回合的迟到回复无法改写当前状态。
- [x] **TS-08，接齐八个游戏工具。** 从现有工具实现提取业务规则与参数模型，迁移观察、动作、安排、记忆、选择、指导和读档恢复。动作调用由 TS 调度层绑定存档与目标，C# 继续执行原生动作。
  - 验收：模型只收到约定的八个工具，参数无效时给出可恢复的工具结果。复用现有碰撞、动画、库存和动作终态用例，重点核对站立、障碍和拾取边界。
- [x] **TS-09，迁移持续目标和共同回合入口。** 接通伙伴、自玩、普通聊天、桌面派工和游戏内交互。实现游戏状态变更后的续作、玩家选择、读档和同一游戏内重连。
  - 验收：模糊目标能根据实际观察持续推进。F8 的新要求在工具边界生效。玩家选择及时保存，F9 后保持玩家控制。读档重建上下文，重连沿用项目会话，游戏事实和动作回执优先。
- [ ] **TS-10，接入第二家模型并验证切换。** 用同一个模型接口接入 OpenAI Responses API，验证两家协议的流式工具消息、用量和取消。服务商列表按实际能力显示模型与推理档位。
  - 验收：同一存档在 DeepSeek 与 OpenAI 间切换，设定、记忆、历史和工作目标能沿用。厂商专有消息和凭据留在对应适配器内。
- [x] **TS-11，记录 Pi Agent Core 采用决定。** 用现有游戏回合用例试验顺序工具调用、工具前置检查、取消、玩家追加要求及原生终态核对。比较维护成本与可测试性。
  - 验收：记录采用或继续使用自有回合的理由及测试证据。该评估不阻塞 TS 自有回合版本发布。
