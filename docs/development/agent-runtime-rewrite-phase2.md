# 阶段 2 · 伙伴数据、游戏工具与模型切换

TypeScript 运行时以 `data/companion.sqlite` 保存角色、手记、历史、目标、安排、待确认事项、提醒和用量，按存档关联。桌面可在空闲时应用另一家模型，角色数据沿用。提醒来自原生观察和已确认的动作回执，按角色设定控制频率。

## 模拟验收

- DeepSeek Chat Completions 与 OpenAI Responses 的模拟服务使用各自的 SSE 格式，通过实际打包的 `pi-ai` 解析工具调用、参数和用量。覆盖断流、鉴权失败、限流和省略用量。
- 在中文和空格路径运行绿色候选，子进程 PATH 仅含 Windows 系统目录。于隔离存档通过 WPF 测试连接、启动游戏、执行原生移动，并分别在模型流式响应和原生移动中按 F9 接管。接着写入伙伴名、手记和目标，在同一个游戏实例从模拟 DeepSeek 切换到模拟 OpenAI。桌面收到后者的回复，SQLite 留有双方用量、同一角色、原对话、手记和未完成目标。
- 自动化回合用例覆盖改派等待原生终态、回执未知时拦截新动作、玩家追加要求到达工具边界、以及换存档后拦截旧回复。两个存档的数据库隔离和重启读取由 SQLite 测试覆盖。

三组固定农活、真实厂商 API、待确认事项的实机操作以及读档和重连的完整实机验收仍待执行。

## Pi Agent Core 采用决定

生产运行时继续使用项目自有回合执行器和 `pi-ai`。用 `@earendil-works/pi-agent-core@1.6.0` 的模拟流分别验证了顺序执行、工具前置检查、原生回执返回后的取消、追加要求、等待玩家决定。

- 顺序模式等待第一个工具返回后再执行第二个，回调可以先核对原生回执。取消信号可以阻止后续工具。
- 原生回执返回后，`steer()` 会在下一次模型请求传入玩家要求。同一条模型回复里的剩余工具已在这之前执行。F8 要在工具边界拦截旧的剩余调用，需要另建队列和前置校验。
- 同一批工具同时含普通观察、待决定项时，单项 `terminate` 无法停止整个批次。需要项目的前置校验挡住后续动作，再用 `finishTurn` 停止模型续跑。原生终态核对和数据库恢复也仍由项目实现。

复现时在临时目录安装 `@earendil-works/pi-agent-core@1.6.0`，将对应探针复制到该目录，用 Node 22.22.2 运行。该依赖限于评估。 [评估探针](../../tests/acceptance/pi-core-probe.mjs)
