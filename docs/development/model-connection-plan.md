# 模型接入与设置页优化方案

星露谷游戏伴侣在桌面提供 OpenAI 官方、DeepSeek 官方和自定义接口三个入口。自定义接口可选择 Chat Completions 或 Responses，并独立选择流式或非流式。实施任务与通过条件见 [模型接入优化 TODO](model-connection-todo.md)。

## 服务商与协议

| 入口 | 请求协议 | 地址 | 模型 |
| --- | --- | --- | --- |
| OpenAI 官方 | Responses | 官方固定地址 | 默认 `gpt-5-mini`，支持选预设模型或手填模型 ID |
| DeepSeek 官方 | Chat Completions | 官方固定地址 | 默认 `deepseek-flash`，支持选预设模型或手填模型 ID |
| 自定义接口 | Chat Completions 或 Responses | 用户填写 HTTPS Base URL | 用户填写网关上的模型 ID |

官方预设默认开启流式，玩家选择服务商、填入 API Key 后即可测试连接。「高级设置」可修改流式开关。官方模型目录提供常用模型和已知能力，手填的模型 ID 通过「测试连接」验证。首批正式预设为 OpenAI 和 DeepSeek，其他兼容网关通过自定义入口接入。

自定义 Base URL 填写接口前缀，例如 `https://gateway.example.com/tenant/v1`。运行时按协议拼接 `chat/completions` 或 `responses`，保留已有的路径前缀，并统一处理尾部斜杠。地址校验需拒绝完整请求路径、查询参数、片段和 URL 内嵌凭据，字段旁给出可直接修正的提示。

## 四种请求方式

| 协议 | 流式开启 | 流式关闭 |
| --- | --- | --- |
| Chat Completions | `stream: true`，从 SSE 收集文本和 `tool_calls` 参数片段 | `stream: false`，读取完整 JSON 中的文本和 `tool_calls` |
| Responses | `stream: true`，处理 SSE 文本、函数调用和完成事件 | `stream: false`，读取完整 JSON 的 `output` 和函数调用项 |

- 两种方式都经过同一个 Agent 回合。适配器负责解析协议、规范化结束原因和用量，并保留向同一厂商回传工具结果所需的调用标识。厂商特有消息留在模型适配器。
- 流式文本边生成边显示，工具参数收齐并校验后才允许执行。流中断时丢弃未完成的工具调用。非流式等待完整响应，界面显示「等待模型响应」，响应返回后统一展示文本或进入工具执行。
- 工具执行后用同一协议、同一流式设置发起下一次模型请求。项目现有的八个工具、控制权校验、原生回执和目标续作沿用当前实现。用量由厂商响应提供，缺失时显示「未记录」。
- 流式以最近一次有效进展计算等待时长。非流式以单次 HTTP 请求计算等待预算，并为「测试连接」的两次模型请求配置匹配的桌面超时。具体默认值由实现阶段结合本机和网关延迟验证。
- F9、取消与改派经现有取消链路终止本地等待。回合失效后丢弃迟到的响应。原生动作已经发出时，按现有终态核对流程收尾，确认后再发下一步。
- 请求严格按玩家所选的协议和流式开关发送。遇到网关拒绝流式、返回格式不符、权限失败或工具调用无效时，在设置区明确展示原因。玩家修改配置后可重新测试。

## 运行时与桌面配置

运行时维护服务商目录，包含服务商 ID、官方协议、默认模型、常用模型和可展示的推理档位。打包目录与桌面 API 从同一份目录生成，WPF 依据返回的能力决定表单内容。官方固定端点与自定义地址校验由运行时统一执行，桌面提供即时提示。

沿用 `/v2/model/providers`、`/v2/model/test` 和 `/v2/model/configure`。模型配置保留 `provider`、`model`、`baseUrl` 和 `reasoning`，新增协议和流式选项。建议自定义使用 `provider: "custom"`，`protocol` 取 `chat-completions` 或 `responses`，`stream` 为布尔值，缺省为 `true`。官方协议由预设确定，运行时校验字段类型及组合。正式字段与示例在实现时同步到 [桌面 API v2](../../contracts/desktop-api/v2.md)。

现有 `openai-compatible` 配置加载为「自定义接口 / Responses / 流式开启」。保留已保存的地址和模型，并沿用该地址对应的 Windows 凭据。API Key 继续按官方服务商或规范化后的自定义端点保存，修改端点后清空输入框，并读取新端点对应凭据。设置文件、日志、诊断和发行包均避免写入密钥与厂商原始错误。

## 设置页与使用流程

保留左侧「设置」入口。在设置页顶部横排三个子 Tab，Tab 栏下方、表单上方放一条横线。每个 Tab 的操作和反馈放在对应表单内。

| 子 Tab | 内容 | 操作与状态 |
| --- | --- | --- |
| 游戏启动 | 游戏目录、游玩方式 | 「保存启动设置」只提交此页配置。游玩方式在游戏重启后生效。 |
| 模型连接 | 服务商、模型和 API Key。自定义接口还显示协议、Base URL 和流式开关。 | 「测试连接」「保存模型设置」。进入存档后，Agent 空闲时可「应用模型」。 |
| 存档偏好 | 当前存档的伙伴名字、相处方向、性格、交流频率、就寝时间以及主动帮忙设置 | 读档后可编辑和保存。未读档时只显示「进入存档后可编辑」。 |

首次打开设置默认进入「游戏启动」。点击「启动游戏」时，如果游戏目录有误，跳转到「游戏启动」并定位到目录。缺少可用模型配置时跳转到「模型连接」，滚动到对应字段、聚焦并显示原因。手动切换子 Tab 保留未保存的输入，API Key 草稿仅保存在窗口内存中。切换存档时，偏好表单按新存档加载。

1. 选官方服务商时，显示 API Key 和已选好的默认模型。可在「高级设置」切换流式，推理档位只在模型有已知支持时显示。
2. 选「自定义接口」时，直接显示协议、Base URL、模型 ID、API Key 和流式开关。切换服务商、端点或模型后，凭据状态和测试结果按当前配置更新。
3. 「测试连接」使用当前表单值，支持读档前运行，结果显示在按钮附近。模型需完成工具调用、读取回执和确认文本。只提供文本的模型给出工具能力提示。
4. 「保存模型设置」写入模型配置和对应凭据，供下次启动使用。「应用模型」在当前游戏会话切换后续回合的模型，沿用存档的角色、手记、历史与工作目标。保存每个子 Tab 时，只写入该页负责的设置。

## 验收范围

先用模拟服务覆盖四种组合的请求、文本、工具往返、用量、取消和错误提示。然后用真实凭据核对两个官方预设及用户提供的第三方网关，有凭据的组合分别记录。最终从干净克隆构建绿色包，在隔离存档核对原生动作、F9、改派和模型切换。记录模型、协议、流式开关、包版本及通过或未执行项。[隔离实机回归](../repeatable-companion-acceptance.md)
