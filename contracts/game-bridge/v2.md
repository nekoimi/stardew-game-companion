# Agent 游戏传输 v2

保留现有 Mod 和运行时之间 WebSocket 的信封结构与原生技能载荷，协议标识从 `0.1` 变更为 `2`。启动发现只传本机端点、会话凭据与游戏绑定。运行时以 `runtime.hello` 声明支持的版本，Mod 以 `mod.welcome` 确认版本与存档。协议不匹配时关闭连接，动作保持禁止。

| 消息 | 关联和处理 |
| --- | --- |
| `world.snapshot` 与控制权状态 | 绑定当前 `saveId` 和 `gameSessionId`，采用该会话中可确认的 `worldRevision`。读档建立新游戏会话，丢弃旧消息。 |
| `chat.submit` / `life.chat.submit` | 游戏内输入和桌面入口进入同一回合服务。用 `requestId` 关联玩家请求和最终回复。 |
| `skill.execute` | 原生动作的 `commandId` 即动作 ID，`taskId` 关联运行时回合；运行时持有回合与玩家请求的关联。发送前检查控制权，沿用现有幂等键。 |
| `skill.cancel` | 依原生命令 ID 取消并等待终态。F9 立即收回控制权，运行时取消模型生成，并核对该动作。 |
| `skill.result` | 按存档、游戏会话、动作 ID 结算一次。重复回执可用于重连核对，避免重复投递或累计效果。 |
| `skill.result.query` / `skill.result.status` | 读取已有回执。 `in-flight` 和 `unknown` 均表示无可结算终态。核对期间保留动作 ID，查询当前状态与观察，后续动作继续受执行权和原生终态约束。 |

每次绑定仅允许一个执行中的原生动作。重新绑定须区分同一游戏内重新连接与新读档；前者保留需要核对的动作，后者重建世界上下文。接管和改派使旧回合失效，迟到的模型请求无法派生新动作。

[共享跨语言样例](examples/v2/action-lifecycle.json) 覆盖版本不匹配、跨读档旧回执、重复回执和未知终态。JSON 样例只维护一份，由 TS 和 C# 共同验证。 [现有信封和原生技能形状](README.md)
