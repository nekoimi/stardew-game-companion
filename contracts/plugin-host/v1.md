# 桌面插件宿主 v1

宿主维护 Windows x64 插件进程和公开接口。已启用且握手成功的运行实例默认获得全部公开接口权限。宿主验证实例身份、所属记录和当前游戏状态。插件的账号、规则及业务页面由插件维护。

## 本地包

ZIP 根目录包含 `plugin.json` 和 `files.json`。清单按对应 Schema 解析，宿主校验 `hostProtocol.min <= 1 <= hostProtocol.max`。安装和启动使用包内相对路径。路径采用正斜杠，每段符合 Windows 文件名规则，拒绝设备名、尾部空格或点、路径穿越、链接、重解析点和大小写冲突。入口为包内 EXE，工作目录为包内目录或 `.`。按数组原样传递参数。

`files.json` 列出除自身外的全部文件，包括 `plugin.json` 与入口。每个文件用小写 SHA256 校验，目录本身无需条目。宿主先校验临时目录中的完整包，再原子更新安装登记。文件哈希校验包内容的完整性。支持的单包上限为解压后 512 MiB、8192 项。再次启动前从安装目录核对清单和列出的文件。

## 生命周期和传输

启动环境提供 `STARDEW_PLUGIN_HOST_URL`（例 `http://127.0.0.1:42119`）、`STARDEW_PLUGIN_TOKEN`、`STARDEW_PLUGIN_DATA_DIR`。所有调用携带 `Authorization: Bearer <token>`。凭据独立于每次运行、以高熵随机数生成，并绑定已安装的插件 ID。默认 15 秒握手、5 秒心跳、15 秒失联和 10 秒停止宽限。停止时只开放心跳以返回停止指示，随后结束实例。默认每实例 60 次请求/10 秒、2 个活动 SSE 连接，JSON 请求体上限 64 KiB。内容类型使用 `application/json`。HTTP 204 无响应体。

| 调用 | 请求 | 成功响应 |
| --- | --- | --- |
| `POST /v1/hello` | `protocolMin`、`protocolMax` 为正整数，已声明设置入口时附 `settingsUrl`。 | 200，`protocolVersion`、`instanceId`、`heartbeatIntervalMs`、`sessionId`。 |
| `POST /v1/heartbeat` | `state` 为 `starting`、`needs_configuration`、`ready`、`degraded` 或 `stopping`，可附不超过 500 字符的 `summary` 与布尔 `restartRequired`。 | 200，`directive` 为 `continue` 或 `stop`，附 `sessionId`。 |
| `POST /v1/messages` | `version: 1`、`type` 为 `status`、`notification` 或 `event`、`messageId`、ISO 时间 `at`、对象 `payload`，可附 `correlationId`。通知的 `payload.text` 最长 500 字符。 | 204，按插件和消息 ID 在当前宿主运行期去重，宿主记录状态和事件，通知可展示。 |
| `GET /v1/state` | 无请求体。 | 200，`{ sessionId, cursor, game, agent }`。 |
| `GET /v1/events?sessionId=…&cursor=…` | 可附逗号分隔的 `topics`。断线续读用 `Last-Event-ID`，其值优先于 `cursor`。空会话 ID 与快照中的 null 对应。 | 200 `text/event-stream`。每帧含 `id`、`event` 与 JSON `data`。 |
| `POST /v1/commands` | `requestId`、去掉首尾空白后 1 至 500 个字符的 `text`、`sessionId`，可附 `correlationId`。 | 202 新受理，200 幂等重试。响应为指令记录。 |
| `GET /v1/commands/{requestId}` | 当前插件自己的请求编号。可在原游戏会话结束后查询。 | 200 指令记录。 |

`settingsUrl` 是当前实例提供的绝对回环 HTTP(S) 地址，接受 `127.0.0.1` 和 `[::1]`。地址不得带用户信息。宿主只打开当前握手成功实例登记的地址。设置在浏览器中的访问验证由插件实现，浏览器页面不接收宿主凭据。

编号、会话 ID、关联 ID 为 1 至 120 个 ASCII 字符，允许字母、数字、下划线、点和连字符。可选字段缺省保留默认语义。客户端忽略未知字段和订阅事件，宿主协议升级通过握手协商。

错误体为 `{ code, message, retryAfterMs? }`。可重试错误必须重新核对当前状态，无需为未受理的尝试生成新编号。

| HTTP | code | 处理 |
| --- | --- | --- |
| 400 | `invalid_request` | 修正字段或 JSON。 |
| 401 | `invalid_instance` | 等待宿主启动并取得新的运行凭据。 |
| 404 | `not_found` | 操作不存在或当前插件没有对应记录。 |
| 409 | `protocol_incompatible`、`not_ready` | 更新兼容版本，或等待插件配置就绪。 |
| 409 | `session_changed`、`cursor_expired` | 取得新快照。旧会话的请求只能查询或原样幂等重试。 |
| 409 | `busy`、`no_game`、`paused`、`player_control`、`recovery_pending`、`waiting_player`、`model_unavailable` | 按状态等待。忙碌与暂停由插件按需重试，玩家保有控制权。 |
| 409 | `request_conflict` | 同一编号的内容已固定。新的任务使用新编号。 |
| 413 | `payload_too_large` | 缩小请求。 |
| 429 | `limit_exceeded` | 减少并发或在重试间隔之后再调用。 |
| 503 | `runtime_unavailable` | 恢复运行时连接后按原编号查询或重试。 |

## 状态和事件

快照的 `sessionId` 随游戏绑定变化，未读档时为 null。游标是宿主事件流的十进制字符串，从 `"0"` 开始，在快照和 SSE 中保持一致。状态快照和游标在同一发布边界读取。保留最近 256 个事件，耗尽续读窗口或会话不符时返回 409。订阅从快照游标之后开始，慢消费者超过缓冲上限时关闭流。切换游戏会话时关闭旧的订阅，客户端重取快照。停止插件时关闭其全部订阅。

`game` 字段限定为 `connected`、`date`（可缺省）和 `timeOfDay`（可缺省）。`agent` 字段限定为 `phase`（`idle`、`thinking`、`executing` 或 `paused`）、`activity`、`controlOwner`（`human` 或 `agent`）及可选 `source`（当前回合的插件 ID）。事件数据为 `{ sessionId, payload }`。

| 主题 | payload |
| --- | --- |
| `game.state` | 与快照 `game` 相同。 |
| `agent.state` | 与快照 `agent` 相同。 |
| `agent.action.completed` | `actionId`、`skillId`、`terminalState`、可选 `completedCount`。 |
| `agent.reply.completed` | `messageId`、`text`、可选 `requestId`。以已送达桌面玩家的完整回复为准，按消息 ID 去重。 |

## Agent 指令与记录归属

宿主通过已认证的内部桌面通道转交插件 ID 和请求，运行时为请求分配内部的回合、请求、目标 UUID。使用绿色包自己的 SQLite 隔离安装数据，并以 `(pluginId, requestId)` 为主键。记录原游戏会话、保存标识、内部关联编号、由规范化文本与会话及关联 ID 计算的指纹。接受记录先持久化，再启动回合。相同编号及内容返回原记录。更改内容返回冲突。响应丢失、重复提交与重启后沿用原编号，重启不自动重放。记录可在原存档退出后查询，查询按插件隔离。

运行时在同一同步临界区检查会话、暂停、控制权、回合、待确认事项、就寝或跨日、动作待核对与已有可执行玩家目标，然后写入受理记录和绑定独立回合。忙碌时由插件重试。插件文字作为外部任务输入，不充当玩家对待确认选项的回答。玩家发送新指令时可改派，暂停和 F9 按现有工具边界执行。插件回合不得覆盖玩家原目标或建立无人确认的跨回合续作，未完成时由玩家明确接续。停用后取消该插件的活动回合并结算。单纯通信掉线允许当前回合完成。

公开记录含 `requestId`、`sessionId`、`status`、`turnEnded`、`goalOutcome`、`actions`，可附 `correlationId`。每条动作沿用公开动作终态字段。只报告原生回执确认的数量，字段缺失时保持缺省。单个模型回合结束与请求目标达成分别表达，`goalOutcome` 为 `unknown`、`achieved`、`partial` 或 `unmet`。目标达成需有游戏观察或回执支持，模型完成输出只证明回合结束。

| status | 来源或转换 |
| --- | --- |
| `accepted` | 通过受理检查且已经持久化。 |
| `running` | 进入绑定回合。 |
| `waiting_player` | 需要玩家处理选择、跨回合或跨日工作。本插件回合结束后由玩家接续。 |
| `completed` | 回合正常结束且原动作均已结算。用 `goalOutcome` 单独表达目标状态。 |
| `partial` | 目标仍有剩余工作并有已确认产出。 |
| `failed`、`cancelled` | 回合失败或取消，保留已确认动作。 |
| `recovery_pending` | 回执待核对或运行时中断。重连时先查询原动作和世界状态，结算可核对的结果。 |

共享样例覆盖包路径诊断、握手、配置状态、无效凭据、游标、受理和回执。包样例的 EXE 内容使用文本字节，仅用于校验安装契约。
